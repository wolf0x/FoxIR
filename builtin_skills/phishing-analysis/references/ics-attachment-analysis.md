# ICS Calendar Attachment Deep-Dive

> Trigger: email attachment contains an `.ics` (text/calendar) file. Do NOT skip it as "just a standard calendar file" — **an ICS is a second delivery channel for malicious links / phishing content** and often reveals the true attack scale.

---

## 1. Why ICS Deserves Deep Analysis

- Mail gateways usually pass `text/calendar` liberally (treated as harmless structured data)
- Recipients see the invite alert in **Outlook / calendar apps** and may click even if they ignore the email
- Attackers stuff phishing links into DESCRIPTION / X-ALT-DESC for **dual-channel delivery** (email body + calendar alert)
- The ATTENDEE list may reveal the **true organization-wide blast radius** (more complete than the To: field)

## 2. Extracting ICS Content

### 2.1 Extract the Attachment from the EML

```
ir_eml path=<eml>  → note the .ics name and size in attachments
```

If the attachment is not on disk, extract it from the raw EML with PowerShell (split on the `Content-Type: text/calendar` boundary), or ask the user for the attachment file.

### 2.2 Read & Parse Key Fields

Read the ICS with a script; **avoid Chinese filenames** on disk (ICS content is often a GBK/UTF-8 mix):

```
Search keywords: ORGANIZER, ATTENDEE, DESCRIPTION, X-ALT-DESC, URL, ATTACH, DTSTART, DTEND, DTSTAMP, UID, SUMMARY, LOCATION, METHOD
```

Reading notes:

- For large files use file_read with line ranges
- Console mojibake is a codepage issue → **write decode/extraction results to a file, then read them with file_read**

## 3. Key Field Triage Table

| Field                           | Role                                         | Malicious / suspicious traits                                                                                                |
| ------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **ORGANIZER**                   | Meeting organizer mailbox                    | Normal if it matches the sender; combine with the email chain to detect a taken-over (ATO) account                           |
| **ATTENDEE**                    | All invited mailboxes                        | 🔴 **Count each one and group by domain** — bulk invites = scaled delivery; security/IT mailboxes included = more suspicious |
| **DESCRIPTION / X-ALT-DESC**    | Invite body (X-ALT-DESC is the HTML variant) | 🔴 **Search for URLs** — the phishing link is often hidden here (dual channel)                                               |
| **URL / ATTACH** fields         | Meeting-attached link/file                   | Standard invites should NOT have them; present = high risk                                                                   |
| **DTSTART→DTEND**               | Meeting time                                 | All-day placeholder (e.g. 07:00–23:00) with no real meeting content = fake                                                   |
| **DTSTAMP**                     | Invite generation time                       | 🔴 Compare with Tencent-Docs creation time and email send time — all within ~30 min = orchestrated attack                    |
| **LOCATION**                    | Venue                                        | Empty = missing meeting elements                                                                                             |
| **CATEGORIES / CLASS / STATUS** | Category / visibility / state                | CONFIRMED/PUBLIC = disguised as a "confirmed public meeting" to boost credibility                                            |
| **X-MICROSOFT-\***              | Outlook compatibility headers                | Attackers use them to reach Outlook users                                                                                    |
| **UID**                         | Unique calendar-object ID                    | Record as an IOC; use for org-wide search of invite copies                                                                   |
| **PRODID / GENERATOR**          | Generator                                    | Identifies the mail vendor (e.g. `-//Mailtech Inc//Coremail Calendar V1//EN`), helps attribute the source                    |

## 4. Encoding & Mojibake Handling

- The `CN=` (display name) parameter in ICS often carries GBK bytes inside a UTF-8 context → shows mojibake (e.g. `CN=̺章`)
- This is known parameter-encoding behavior of domestic Chinese enterprise mail (Coremail etc.), **not a malicious trait** — but it can CONFIRM the ICS was natively generated by that vendor (not forged by a third party)
- Always write the extract to a UTF-8 file first, then read it — never trust the console codepage

## 5. Timestamp Self-Proof Analysis (Core Technique)

Compare these timestamps side by side (all converted to UTC+8):

| Event                                  | Source                      |
| -------------------------------------- | --------------------------- |
| Cloud-doc / landing-page creation time | opendoc API `createTime`    |
| Email send time                        | EML Date / Received headers |
| ICS DTSTAMP / invite generation        | The ICS file                |
| Internal forward time                  | EML References chain        |

Judgment: **doc created first → ICS + email sent within minutes → internal forward follows** — all three completed within 30–40 minutes = orchestrated attack chain, not normal business rhythm.

## 6. ATTENDEE Scale Analysis

- Group all ATTENDEEs by `@domain` and count
- Identify subsidiary / affiliated-company domains (different domains = cross-entity delivery)
- Project-group mailboxes (e.g. n1048en@...) alongside personal named mailboxes = full blast
- `netsec` / `security`-type mailboxes included → attacker did no targeted exclusion = spray-and-pray

## 7. Verdict & Integration

- DESCRIPTION contains an external link → **that domain MUST get threat intel (TB/VT)**
- External link hits a malicious verdict → **PHISHING, hard evidence** (even if the email body/domain looks normal)
- Large ATTENDEE count + multiple domains → escalate to **organization-wide phishing event**; remediation scope grows from "single host" to "org-wide sweep"
- The ICS itself is a standard VCALENDAR (no exploit payload) → do NOT classify it as a malicious file, but DO classify it as a **malicious delivery vehicle**

## 8. IOC Extraction

- ICS file SHA256 / MD5
- UID (e.g. `00a19ca7-a36c-463a-b457-293d7406bbd3`) — use to search the whole mail/calendar store for that invite
- ORGANIZER mailbox (may be a taken-over account)
- Full ATTENDEE mailbox list (de-identified, used to scope the sweep)
- All URLs embedded in DESCRIPTION

## 9. Real Case Post-Mortem (2026-08-27 COSCO case)

- ATT00003.ics: standard Coremail-generated meeting invite, ORGANIZER = zhang.san@abc.com (real mailbox)
- DESCRIPTION repeatedly embeds the Tencent-Docs link (same as email body) → dual channel
- ATTENDEE = **99 unique mailboxes**: 62 project groups + subsidiaries + overseas staff + netsec security mailbox
- DTSTAMP 2026-08-19 06:57 vs doc creation 06:49 vs forward 07:23 → all done within 34 minutes
- Conclusion: the zhang.yanhong account was likely taken over (ATO); the calendar invite was used to spread the phishing link org-wide
